Verify it

  1. Download all three into one folder. 
    curl -O https://hifidelity.app/verify/PDG-LAYER-001.json
curl -O https://hifidelity.app/verify/provenance_log.jsonl
curl -O https://hifidelity.app/verify/provenance.py
  2. Check the chain is internally consistent. 
    python3 provenance.py verify

    Each record links to the one before it by hash, so altering any past entry breaks every entry after it. Expect CHAIN OK.

  3. Check the content matches the stamp. 
    python3 provenance.py check PDG-LAYER-001.json

    This recomputes the hash from the file you just downloaded and compares it to the logged value. Expect MATCH — this exact content was stamped. Change one character in the JSON and it will fail.

  4. Check the signature. 
    python3 provenance.py verifysig

    The chain head is signed with Ed25519. This confirms the signature verifies under the public key above — that the holder of that key asserts this chain, not merely that the content exists.

  5. Or skip our tools entirely.

    The content hash is a SHA-256 over components 1–8 canonicalized as JSON with sorted keys and no whitespace. The signature is standard Ed25519 over the 64-character chain-head string, UTF-8 encoded — verifiable with openssl, ssh-keygen, PyNaCl, python-cryptography, or any library you already trust.

    That is the point. Our verifier is a convenience, not a dependency. Nothing about this claim requires you to trust code we wrote — and ed25519_ref.py ships with the RFC 8032 test vector so you can confirm it is a correct implementation before running it:

    python3 ed25519_ref.py

What this proves, and what it doesn't

It proves that this exact content existed as a single unaltered unit, that the chain has not been rewritten, and that the author identity is bound inside the hash rather than attached to it — the email cannot be swapped without changing the content hash.

It proves that the holder of the published Ed25519 key asserts this chain. A hash alone establishes that content existed in a fixed form; anyone can compute a SHA-256. The signature binds the claim to a key only its holder can use.

It does not prove when the key was held. The signature is dated 6 August 2026, so it attests the chain as of that date — it does not independently establish the June stamp. Nor does a signature establish identity on its own: it proves control of a key, and the link between that key and a person is a separate matter. We would rather state this than let the word "verified" do work it hasn't earned.

Independent record The page carrying these hashes is archived by the Internet Archive, which is not operated by us. That capture is dated 6 August 2026 — it corroborates the hashes, not the June date. The June date rests on the chain itself and on a contemporaneous timestamped email record.

We publish the limits alongside the claim because a claim nobody can check is a slogan. Trust is built into how a system operates — local-first, transparent, user-owned — not asserted as a label.
